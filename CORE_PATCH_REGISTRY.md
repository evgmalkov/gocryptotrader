# Core Patch Registry

> Реестр изменений ветки `scibot` **вне** каталога `exchanges/mexc/*` — то есть правок кода,
> общего для всех площадок (`ADR-218` `GCTU-14`/`GCTU-19`/`GCTU-26`).
>
> **Анонимных правок upstream не существует.** Каждая правка вне своего каталога несёт запись:
> ID · файл · причина · владелец · **измеримое условие удаления** · применение · судьба ·
> происхождение. Отсутствие записи = дефект, а не мелочь.

Создан пустым **до** анализа необходимости патчей: вывод «патч нужен» не должен существовать
отдельно от своей записи.

**База:** `thrasher-corp/gocryptotrader@master` = `1c8597ebc20bbe62c15e6c6e2bff84e964c0fb00`.
**Источник унаследованных правок:** `samuael/gocryptotrader@mexc` = `81949b5aa40f24eb2a459b9bd28476b23f8935e9`.
Апстрим под MIT; производная работа сохраняет атрибуцию (`GCTU-21`).

## Ответ шага 3А — числом

Правок ядра в исходной дельте — **5**. После разбора:

| | Число | Какие |
|---|---:|---|
| Необходимы | **3** | `CP-001`, `CP-004`, `CP-005` (последний — переписан в `S6`, см. его запись) |
| Не нужны | **2** | `CP-002`, `CP-003` — доказано, см. записи |

**Для сборки** из пяти необходима **одна** (`CP-001`): без неё `go build ./...` даёт ровно две
ошибки — `undefined: order.Holding`, `undefined: order.SystemHolding`
(`exchanges/mexc/futures_websocket.go:264,266`). Остальные четыре сборку не ломают — их
необходимость либо доказана иначе (`CP-004`, `CP-005`), либо опровергнута (`CP-002`, `CP-003`).

Различение существенно: «собирается без патча» — **не** синоним «патч не нужен». Регистрация
биржи и распаковка её фреймов компилятору невидимы.

### `CP-005` — `parseBinaryResponse`: не-GZIP бинарный фрейм

**Переписан 2026-08-02 (стрим `S6`) по заранее объявленному и ВЫПОЛНЕННОМУ условию.**

| Поле | Значение |
|---|---|
| **Файлы** | `exchange/websocket/connection.go` (**+12 / −0**), `exchange/websocket/manager.go` (+1) |
| **Класс** | Core Patch — **аддитивный шов**, не смена поведения |
| **Причина** | MEXC шлёт protobuf **без сжатия**; апстримовый разбор считает любой не-GZIP бинарный фрейм raw `flate`-потоком и портит его |
| **Что было до `S6`** | унаследованная правка переписывала общий `parseBinaryResponse` (`+28 / −8`), меняя поведение **для всех площадок**. Нарушение `GCTU-29` было **измерено**: апстримовый `TestParseBinaryResponse` зелёный на чистом `master`, красный с патчем (2 ассерта) |
| **Что стало** | необязательное поле `ConnectionSetup.BinaryMessageDecoder func([]byte) ([]byte, error)`; **`nil` = апстримовое поведение дословно**. Логика MEXC переехала в свой слой — `exchanges/mexc/binary_frames.go::decodeBinaryFrame`, прикреплена в обеих точках настройки соединения (spot + futures) |
| **Результат измерением** | гейт A `exchanges/mexc` **61 PASS / 0 FAIL** (тождественно эталону `S5`) · гейт B `exchange/websocket` **60 → 61 PASS / 0 FAIL** (`TestParseBinaryResponse` позеленел). Гейты падают независимо — слитый не сказал бы, что именно сломалось |
| **Владелец** | зона EXCHANGE |
| **Условие удаления** (измеримое) | влит PR в апстрим, добавляющий точку расширения разбора бинарного фрейма (шов написан как кандидат в апстрим: аддитивен, не меняет дефолта, не упоминает площадку) |
| **Применение** | `APPLIED` (в новой форме) |
| **Судьба** | `UPSTREAM_PENDING` — **предложение подготовлено 2026-08-02**: ветка `upstream-pr/ws-binary-decoder` от чистого `upstream/master`, коммит `3a6cb6ef`, `+57/−0` в трёх файлах. Отправка — решение оператора; номера PR пока нет |
| **Происхождение** | `INHERITED` → **`REWORKED`**. Существенно для PR: **предлагаемый апстриму код — `OURS` целиком** (сам шов написан нами), логика MEXC в предложение не входит и остаётся у нас. Лицензионного вопроса о чужом коде здесь не возникает |

**Целевая форма из `ADR-218` ам.№7 недостижима, и это измеренный факт об устройстве апстрима, а не
недоработка.** Ам.№7 называл «ветвление локализовано в MEXC-адаптере, общий код не тронут»
единственной формой, при которой патч **перестаёт существовать**. Проверено кодом: `connection`
конструируется исключительно внутри `Manager.createConnectionFromSetup`, его поля не экспортируются,
а в `ConnectionSetup` нет ни одного поля, влияющего на разбор фрейма. Адаптер площадки **физически
не имеет точки влияния** на `parseBinaryResponse` — значит выбор был не между «патч есть» и «патча
нет», а между тремя формами патча:

| Форма | Оценка |
|---|---|
| унаследованная (переписан общий разбор) | `GCTU-29` нарушен — доказано тестом апстрима |
| `if venue == MEXC` в общем коде | `GCTU-29` соблюдён, но общий слой знает про площадку; в апстрим такое не предложишь |
| **аддитивный необязательный шов** (выбрана) | `GCTU-29` соблюдён **по построению** (дефолт = апстрим), общий код не знает про MEXC, поверхность конфликта минимальна, и патч становится **реальным** кандидатом в апстрим — то есть условие его удаления перестаёт быть декоративным |

**Цена патча снизилась измеримо, и это главный результат стрима:** девять удалённых строк апстрима
исчезли полностью — дельта ядра стала **чисто аддитивной**, `+43 / −9` → **`+26 / −0`**.

## Кандидат в апстрим — подготовлен, не отправлен

**Ветка:** `upstream-pr/ws-binary-decoder` (от `upstream/master` = `1c8597eb`), коммит `3a6cb6ef`.
**Состав:** `ConnectionSetup.BinaryMessageDecoder` + проброс + два теста. `+57/−0`, MEXC не входит.

**Проверено:** `go build ./...` чисто · `go test -race ./exchange/websocket/` — `ok` ·
`go test ./exchange/... ./exchanges/order/...` — `ok` · `go vet` чист · `gofmt` чист на
нормализованных копиях (шум `gofmt -l` в рабочей копии — CRLF Windows, задевает и нетронутые файлы).

**Почему именно этот патч идёт первым.** Из трёх наших `APPLIED`-записей он единственный, чья
ценность для апстрима не зависит от MEXC: точка расширения полезна любой площадке с нестандартными
бинарными фреймами. `CP-001` (статусы `Holding`/`SystemHolding`) без MEXC не имеет потребителя, а
`CP-004` — регистрация, которая уйдёт вместе со слоем.

**Формальная оговорка (`ADR-218` ам.№7).** Критерий готовности к PR требует трёх условий: `GCTU-4`
закрыт ✅, frozen tests зелёные ✅, дивергенция по ядру не растёт **два релиза апстрима подряд** —
последнее **не наблюдалось и наблюдаться не могло**: релизов с момента перехода ноль. Условие
писалось про предложение нашей реализации MEXC («предлагать код, дающий 47 453 ошибки, вредно») — к
патчу, не содержащему MEXC, его мотив не относится. Расхождение записано, а не обойдено молча.

## Vendor Extension — происхождение (`GCTU-25`)

44 файла коммита `vendor(mexc): …` (34 в `exchanges/mexc/*` + 10 регистрационных вне его) —
происхождение **`INHERITED`** целиком: приняты от автора форка как есть, с атрибуцией.
Последующие наши правки в этих файлах переводят затронутый код в `REWORKED`; первая такая —
`orderStatusFromString` (`CP-002`).

Наблюдение к стоимости обновления: все пять патчей ядра и весь класс C приложились к апстриму,
ушедшему вперёд на **286** коммитов, **без единого конфликта** (`git apply --check` — чисто по
каждому). Пересечение дельты с отставанием оценивалось в 11 файлов и один семантический
конфликт; семантический конфликт подтвердился ровно один — `CP-005`, и он виден не диффом, а
тестом.
