# Core Patch Registry

> Реестр изменений ветки `scibot` **вне** каталога `exchanges/mexc/*` — то есть правок кода,
> общего для всех площадок (`ADR-218` `GCTU-14`/`GCTU-19`/`GCTU-26`).
>
> **Анонимных правок upstream не существует.** Каждая правка вне своего каталога несёт запись:
> ID · файл · причина · владелец · **измеримое условие удаления** · применение · судьба ·
> происхождение. Отсутствие записи = дефект, а не мелочь.

Создан пустым **до** анализа необходимости патчей: вывод «патч нужен» не должен существовать
отдельно от своей записи.

**База:** `thrasher-corp/gocryptotrader@master` = `1c8597ebc20bbe62c15e6c6e2bff84e964c0fb00`.
**Источник унаследованных правок:** `samuael/gocryptotrader@mexc` = `81949b5aa40f24eb2a459b9bd28476b23f8935e9`.
Апстрим под MIT; производная работа сохраняет атрибуцию (`GCTU-21`).

## Ответ шага 3А — числом

Правок ядра в исходной дельте — **5**. После разбора:

| | Число | Какие |
|---|---:|---|
| Необходимы | **3** | `CP-001`, `CP-004`, `CP-005` |
| Не нужны | **2** | `CP-002`, `CP-003` — доказано, см. записи |

**Для сборки** из пяти необходима **одна** (`CP-001`): без неё `go build ./...` даёт ровно две
ошибки — `undefined: order.Holding`, `undefined: order.SystemHolding`
(`exchanges/mexc/futures_websocket.go:264,266`). Остальные четыре сборку не ломают — их
необходимость либо доказана иначе (`CP-004`, `CP-005`), либо опровергнута (`CP-002`, `CP-003`).

Различение существенно: «собирается без патча» — **не** синоним «патч не нужен». Регистрация
биржи и распаковка её фреймов компилятору невидимы.

## Записи

### `CP-001` — статусы ордера `Holding` / `SystemHolding`

| Поле | Значение |
|---|---|
| **Файлы** | `exchanges/order/order_types.go` (+2), `exchanges/order/orders.go` (+8) |
| **Класс** | Core Patch (поведение общего кода) |
| **Причина** | MEXC futures отдаёт состояния `HOLDING` / `SYSTEM_HOLDING`; в общем перечислении `order.Status` их нет |
| **Почему не в своём слое** | `order.Status` — перечисление на `iota` в общем пакете. Объявить свои значения из `exchanges/mexc` можно только числами, которые общий `String()` не знает (напечатает `UNKNOWN`) и которые столкнутся с будущими значениями апстрима. Расширение перечисления из вендора невозможно без риска коллизии |
| **Безопасность формы** | значения добавлены **в конец** блока `iota` — существующие константы не сдвигаются |
| **Владелец** | зона EXCHANGE |
| **Условие удаления** (измеримое) | влит PR в апстрим, добавляющий эти два статуса, **либо** апстрим принял `exchanges/mexc` (тогда ретайрится весь слой, `GCTU-16`) |
| **Применение** | `APPLIED` |
| **Судьба** | `UPSTREAM_PENDING` (номера PR нет — предложение не сделано, `ADR-218` ам.№7: сначала долг `GCTU-4`, потом PR) |
| **Происхождение** | `INHERITED` |
| **Проверено** | `go test ./exchanges/order/...` — `ok` |

| **Судьба** | — (патча больше нет; знание живёт в Vendor Extension) |

### `CP-003` — `TenMilliseconds` в `SupportedIntervals`

| Поле | Значение |
|---|---|
| **Файл** | `exchanges/kline/kline_types.go` (+1) |

### `CP-005` — `parseBinaryResponse`: не-GZIP бинарный фрейм

| Поле | Значение |
|---|---|
| **Файл** | `exchange/websocket/connection.go` (+28/−8) |
| **Класс** | Core Patch — **самая опасная правка набора** (общий websocket-слой) |
| **Причина** | MEXC шлёт protobuf **без сжатия**; апстримовая ветка безусловно прогоняла любой не-GZIP бинарный фрейм через raw `flate` и портила его. Мотив законный, патч блокирующий |
| **Чем опасен** (**измерено, а не предположено**) | апстримовый тест `TestParseBinaryResponse` (`exchange/websocket/manager_test.go`) на чистом `master` — **зелёный**; с этим патчем — **красный, 2 ассерта**: (а) `parseBinaryResponse should deflate` — raw DEFLATE без zlib-заголовка возвращается сырым вместо распакованного; (б) пустой вход даёт `no response: empty binary response` вместо `unexpected EOF`. То есть `GCTU-29` нарушен, и это доказано собственным контрактом апстрима |
| **Кто ещё затронут** | `EnableCompression: true` во всём дереве ставят **только** `exchanges/mexc/websocket.go:65` и `futures_websocket.go:71` — других площадок с явной компрессией нет. Это **сужает**, но не снимает риск: `parseBinaryResponse` вызывается для любого бинарного фрейма, а не только при включённой компрессии |
| **Владелец** | зона EXCHANGE |
| **Условие удаления** (измеримое) | ветвление перенесено в MEXC-адаптер, общий код возвращён к апстримовому виду, и `TestParseBinaryResponse` **зелёный** (стрим S6, гейт B). Целевая форма — исчезновение патча, а не его смягчение (`ADR-218` ам.№7) |
| **Применение** | `APPLIED` — **промежуточное состояние, объявленное заранее** (`ADR-218` ам.№6: сначала работающая база, потом заморозка эталона, потом переписывание) |
| **Судьба** | `UPSTREAM_PENDING` |
| **Происхождение** | `INHERITED` |

## Vendor Extension — происхождение (`GCTU-25`)

44 файла коммита `vendor(mexc): …` (34 в `exchanges/mexc/*` + 10 регистрационных вне его) —
происхождение **`INHERITED`** целиком: приняты от автора форка как есть, с атрибуцией.
Последующие наши правки в этих файлах переводят затронутый код в `REWORKED`; первая такая —
`orderStatusFromString` (`CP-002`).

Наблюдение к стоимости обновления: все пять патчей ядра и весь класс C приложились к апстриму,
ушедшему вперёд на **286** коммитов, **без единого конфликта** (`git apply --check` — чисто по
каждому). Пересечение дельты с отставанием оценивалось в 11 файлов и один семантический
конфликт; семантический конфликт подтвердился ровно один — `CP-005`, и он виден не диффом, а
тестом.
